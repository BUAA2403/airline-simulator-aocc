# 本地连接与长期同步的独立复核

日期：2026-10-17。复核范围：`server/index.mjs`、`adapter.mjs`、`sync.mjs`、`vault.mjs`、`store.mjs`、`normalize.mjs`，以及本地会话扩展与 API 的连接语义。

本复核仅使用本地 HTTP 服务、内存凭据保管库、模拟游戏适配器和内存 SQLite；没有向生产游戏服务发送请求。回归测试文件为 `tests/security.test.mjs`，运行方式：`node --test tests/security.test.mjs`。

复核结果：主开发修正下述问题后，11 项安全与连接生命周期回归测试全部通过。此环境默认沙箱禁止本机套接字连接，测试经批准在允许本机回环通信的模式下完成；没有扩大到游戏生产网络。

## 已发现并交由主开发修正的项目

1. **静态文档路径越界**：原文档路由把仓库根目录作为允许读取的基目录，编码的父目录分隔符可读取服务端源码或本地凭据文件。应将允许范围固定到 `docs/` 子目录，并在解码与规范化后再次验证路径。
2. **账号替换继承旧会话**：原连接逻辑把新访问令牌合并到旧配置，可能保留之前账号的刷新令牌和已推断航空公司 ID。新增会话时应替换凭据与账号映射；仅修改同步设置时才保留现有会话。
3. **断开与异步保存竞争**：成功同步在异步保存后没有再次核对连接代次，断开期间的旧请求可能把状态改回已连接并重建定时器。每个关键异步保存结束后都需验证代次。
4. **凭据文件保存竞争**：共享临时文件且没有写队列时，续期、重新配对、断开可能相互覆盖。应按调用顺序串行保存，并使用唯一临时文件。
5. **历史图混入其他航空公司**：原历史查询按小时聚合所有快照。应同时按航空公司 ID 与来源筛选，避免账户切换或导入快照混入经营趋势。
6. **关闭后的旧请求访问数据库**：后台同步完成后的通知可能读取已关闭的数据库。关闭后应抑制旧通知和新定时任务。
7. **桥接失败误报成功**：原会话桥接对 `ok:false` 仍返回 HTTP 200，使扩展显示连接成功。失败时须返回非成功状态码，前端显示固定、安全的失败消息。
8. **桥接来源验证**：除受支持的扩展来源和本机同源调用外，其他网站的请求应在解析凭据或消耗配对码前拒绝。一次性随机码仍是实际配对授权的必要条件。

## 回归覆盖

- 本机 Host 白名单抵抗 DNS rebinding；拒绝其他网站读取状态、生成配对码或修改配置。
- 扩展跨域预检仅允许桥接端点；一次性配对码长度、有效期、重复使用限制。
- 状态、导出、健康检查和错误响应中没有访问令牌或刷新令牌。
- 编码的正斜杠和 Windows 反斜杠不能逃出文档目录。
- 断开清除持久化会话并保留已成功取得的历史快照。
- 替换账号、保存期间断开、读取期间关闭的异步边界。
- 不同航空公司及手动导入来源的小时历史相互隔离。

## 明确的运行边界

- 本机服务只监听回环地址，未设计为直接暴露到公网的多用户服务。
- 现有官方会话并不是独立的只读凭据；只读边界由服务端固定游戏域名、固定表 / 读取 RPC 与 GET 请求建立。续期使用官方标准认证 POST，不能据此允许游戏业务写入。
- 游戏运营数据适配尚需用户自己完成官方登录和本机配对后验证；离线测试无法证明用户实际账户的接口授权、实时坐标或经营字段可用。
- 使用同一个可轮换刷新令牌的官方浏览器与本机服务可能互相触发重新登录。应在刷新失效时停止密集重试并清晰要求重新配对。
- 数据库当前按快照条数保留历史；大机队长期运行的磁盘占用仍应结合实际快照大小观察，并根据实际运行需要调整保留策略。
